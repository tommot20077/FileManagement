## 檔案管理平台後端介紹

### 範例網站: [點擊前往](https://file.900303.xyz/)

- **帳號**: `user123`
- **密碼**: `Aa12345678`

### 簡介

本系統後端基於 **Spring 框架**，採用 **WebFlux 反應式非阻塞架構**，確保高併發環境下的高效能與低資源占用。透過
**策略模式、可擴充的架構設計與完整的 API 文件支援**，提供靈活、可擴展且安全的檔案管理解決方案，適用於各種業務場景。

---

### 主要特色

#### 1. 可擴展的檔案管理架構

- 採用 **策略模式**，根據需求選擇不同的檔案處理策略，如 **一般檔案、資料夾等**。
- 透過 **統一接口設計**，新增特殊檔案類型時僅需擴充對應的處理邏輯，而不影響其他功能。

#### 2. 多種檔案上傳方式以及擴充功能

- **標準單檔上傳**：適用於一般檔案。
- **大檔案分片上傳**：提升傳輸穩定性，確保大型檔案可恢復式上傳。
- **支援 HTTP & WebSocket 上傳**：根據應用場景選擇最佳傳輸方式，提高使用者體驗。
- **MD5 檢查**：上傳檔案前計算 MD5 碼，當檔案已存在時，系統會自動跳過上傳，直接返回檔案資訊，提升上傳效率。
    - 快速檔案排重: 快速刪除重複檔案，避免不必要的存儲浪費。
    - 穩定性: MD5 碼可用於檔案完整性驗證，確保檔案在傳輸過程中數據未損壞。
    - 安全性: 若檔案具有威脅性，管理員可快速定位所有問題檔案，並進行處理。

#### 3. 自定義檔案類型

- **多樣式檔案類型支援**: 自動辨識檔案類型，並根據檔案類型提供不同的處理邏輯。
- **線上可編輯檔案**: 支援線上編輯檔案，以及檔案紀錄版本管理，方便用戶隨時查看、還原檔案歷史紀錄， 提高檔案管理效率。

#### 4. 系統保護架構

- **Bucket Limit (桶限制)**：防止單一用戶過度使用資源，確保系統穩定性。
- **Circuit Breaker (斷路器)**：防止系統過載，在服務崩潰時切換到安全模式，保護系統。
- **Resilience4j 限流保護**：避免過多請求導致性能下降。

#### 5. 靈活的權限與分享管理

- **預設四種權限控制策略**，允許自定義權限規則，確保檔案安全。
- **檔案分享機制**：用戶可透過動態設定權限共享檔案。

#### 6. 高效的系統架構

- **WebFlux 非阻塞架構** 提供高效的 I/O 處理，適用於高併發環境。
- **接口+實現類設計**：透過標準接口，快速擴展新功能。
- **全局錯誤處理**：統一處理異常，提升系統穩定性與可維護性。

#### 7. 完整的日誌與用戶行為監控

- **AOP (面向切面編程) + 自定義註解**，統一記錄日誌，減少耦合。
- **請求 ID 追蹤機制**，快速定位錯誤，提高除錯效率。

#### 8. 高效的快取與資料庫整合

- **自定義快取管理器**：減少資料庫查詢，提高系統效能。
- **檔案快取**：系統會將上傳的檔案快取到 Redis 中，當用戶再次上傳相同檔案時，系統會直接從快取中獲取檔案資訊。
- **多種資料庫支援**：
    - **MySQL**：儲存用戶資訊與檔案元數據。
    - **MongoDB GridFS**：提供彈性檔案存儲。
    - **Redis**：快取用戶數據，提升存取效能。

#### 9. 安全性保障

- **多重驗證模式**：支援 JWT、Cookies 等身份驗證方式。
- **端口防護機制**：透過 CSRF 憑證、CORS、HSTS 等手段加強系統安全性。
- **檔案上傳安全性**：檔案上傳後，系統會對檔案進行病毒掃描，確保檔案安全。
- **OpenAPI 3.0 規範**：確保 API 安全性與一致性，並提供 Swagger UI 可視化管理。

#### 10. 容器化部署與自動化 CI/CD

- **Docker 容器化部署**：確保環境一致性，簡化部署與維護。
- **Docker Compose**：管理多個服務，支援一鍵部署。
- **Github CI/CD**：自動化部署流程，提升開發效率。
- **Nginx 反向代理**：提升系統性能與安全性。

#### 11. 用戶檔案管理與查詢優化

- **樹狀結構儲存資料夾關聯**：即使目錄層級複雜，也能快速查詢。
- **快速索引與篩選機制**，提升大規模資料的檔案檢索效能。
- **自定義檔案查詢條件**，支援多種查詢方式，如檔案名稱、修改時間、類型等，並支援多條件組合查詢。

#### 12. 彈性配置與高可用設計

- **自定義線程池**，根據系統負載自適應調整，提高任務處理效率。
- **RESTful API 設計**：統一 API 規範，提升前端開發效率。
- **提供大量可配置參數**，如檔案大小限制、上傳數量限制、快取時間等，可根據需求進行調整。

## 安裝與使用

### 1. **環境要求**

- **docker**: 20.10.0+
- **docker-compose**: 1.29.2+

### 2. **安裝步驟**

1. 下載位於 [docker/src](https://github.com/tommot20077/FileManagement/tree/develop/docker/src)
   內的所有檔案或是直接下載打包好的 [Release](https://github.com/tommot20077/FileManagement/releases/tag/latest) (
   請不要更動內部檔案的目錄結構以及名稱)。
2. 將下載的檔案放到執行的目錄下(如果是下載的壓縮檔，則解壓縮到目標目錄)。
3. 下載的設定黨已經做好設定，如果有需要自定義某修設定需在啟動之前請先確認各類的設定檔案
    - `docker-compose.yml`：設定各個服務的版本、網路、端口等資訊，如果有需要調整請參考註解並更動相關樹定。
    - `Dockerfile`：設定應用程式的建置過程，包含安裝 JDK、Maven 等必要工具。
    - `wait-for-it.sh`：確保資料庫服務啟動後再啟動應用程式，避免因為資料庫尚未啟動而導致應用程式無法連線。
    - `application.yml`：設定應用程式的基本參數，如資料庫連線、快取設定等。 (
      更詳細的設定請參考 [範例設定檔案](https://github.com/tommot20077/FileManagement/blob/develop/src/main/resources/application-demo.yml))
    - 各資料庫的設定檔案。(如果在其他設定有進行更改這邊也需要同步處理)
4. 需要手動配置的參數為
    - `application.yml` 中的
        - `spring.datasource.password`
        - `spring.data.mongodb.url`
        - `spring.data.redis.password` (需設定與 `redis.conf` 中的 `requirepass` 一致)
        - `security.jwt-token.secret`
    - `docker-compose.yml` 中的
        - `MYSQL_ROOT_PASSWORD`
        - `MONGO_INITDB_ROOT_USERNAME`
        - `MONGO_INITDB_ROOT_PASSWORD`
5. 服務控制
    1. 啟動服務 在終端機中進入到下載的目錄下，執行以下指令啟動服務
       ```bash
       docker-compose up -d
       ```
    2. 關閉服務
       ```bash
       docker-compose down
       ```
    3. 查看服務狀態
        ```bash
        docker-compose ps
        ```

6. 補充:
    - 如果需要安裝前端頁面的話可以將 `docker-compose.yml` 中的 `frontend`
      註釋移除，並下載前端 [Dockerfile](https://github.com/tommot20077/FileManagementWeb/blob/master/docker/Dockerfile-front)
      放入當前目錄下，然後執行以下指令
        ```bash
        docker-compose up -d filemanager_front
        ```

### 3. **測試結果**

以下是針對 **Reactive (WebFlux)** 與 **Blocking (MVC)** 架構的性能測試結果，主要針對以下幾個項目進行比較：

- **平均處理時間 (s)**: 每個請求的平均處理時間，此數值越低越好

- **請求每秒 (RPS)**: 每秒處理的請求數量，此數值越高越好

- **執行占用 CPU (%)**: 系統在執行過程中 CPU 的平均使用率，此數值越低越好

- **執行占用 RAM (%)**: 系統在執行過程中 RAM 的平均使用率，此數值越低越好

- **錯誤率 (%)**: 請求處理過程中的錯誤率，此數值越低越好
